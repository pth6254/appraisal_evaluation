# 국가법령정보센터 부동산 법령 수집

이 폴더는 공식 API의 현행 법령을 보존하는 별도 자료 저장소다. 기존 `chat_chunks`의 요약 지식·분쟁 설명·판례와 섞지 않는다. 2026-09-10 실제 API로 기본 대상 24개 전부 수집했다. 조문 2,175개와 API에서 `전문`으로 표시한 편장절 제목 등 217개, 총 2,392개 본문 단위를 보존했다. 부칙은 24개 법령, 별표 정보는 11개 법령에서 확인했다.

## 실행

국가법령정보 공동활용에서 발급받은 API 인증값을 프로젝트 `.env`의 `LAW_OC_KEY` 또는 기존 `LAW_API_KEY`에 설정한다. 둘 다 있으면 `LAW_OC_KEY`가 우선한다. 현재 프로젝트의 `LAW_API_KEY`로 실제 수집에 성공했다. 인증값을 채팅·로그·Git에 남기지 않는다.

```bash
# 대상 확인 (인증 불필요)
./venv-wsl/bin/python -m backend.tools.collect_property_laws --list

# 우선 법령 한 건으로 접근 권한과 응답 확인
./venv-wsl/bin/python -m backend.tools.collect_property_laws --laws "주택임대차보호법"

# 기본 대상 24개 수집
./venv-wsl/bin/python -m backend.tools.collect_property_laws
```

초기 대상: 임대차·중개·거래 신고·등기·실명 등기·주택·건축·국토계획·정비사업·집합건물·가격공시 관련 법률과 시행령·등기규칙이다. 부동산 관련 법령 전체를 망라하지 않는다. 민법·세법·행정규칙·자치법규·판례는 이번 기본 목록에서 제외한다.

## 보존 내용

- `raw.json`: API JSON 응답. 인증값 포함 링크가 있을 경우 인증 부분만 마스킹한다.
- `law.json`: 법령 ID·버전 ID·시행일·공포일·출처 링크·수집 시각과 조·항·호·목 본문. 긴 조문도 잘라내지 않는다.
- 부칙·별표: 원래 구조와 첨부 링크를 보존한다. PDF·HWP 첨부파일 자체는 다운로드하지 않는다.
- `manifest_*.json`: 법령별 성공·실패 기록. 실패가 하나라도 있으면 종료 코드 1, 인증값 누락은 2다.

동일 원문은 같은 경로에 저장되고, 변경된 원문은 별도 경로에 보존된다. 이전 자료는 삭제하지 않는다. 법령 자료는 Git에서 제외된다. 임베딩 생성·DB 적재·챗봇 검색 연결은 이 명령의 범위에 포함하지 않는다.

공식 명세:
- [현행법령 시행일 기준 목록](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdListGuide): `target=eflaw`, `nw=3`으로 현행만 검색하고 법령명 정확 일치 확인.
- [현행법령 시행일 기준 본문](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdInfoGuide): 검색 결과의 `MST`·`efYd`로 버전을 지정해 본문 조회.

실제 API 접근, 24개 법령명 정확 일치, 시행일 확인, 원문·정규화 파일 저장을 검증했다. 저장 파일에서 설정된 인증값이 검출되지 않음도 확인했다. 수집 단계에서 백엔드 849개 테스트·오프라인 평가 33개 및 프론트엔드 타입 검사·린트·빌드가 통과했다.

## 임베딩과 pgvector 적재

2026-09-10 실제 적재 완료: 법령 24개 모두 `ready / active`, 벡터 4,115개 모두 2,560차원이다. 본문 2,510개·부칙 1,333개·별표 텍스트 272개 청크다. 동일 manifest 재실행 시 추가 임베딩은 0개이고 총 건수도 유지됐다. 기존 `chat_chunks` 22개는 변경하지 않았다. 백엔드 이미지도 새 모델·마이그레이션을 포함해 재빌드했으며 `/health` 정상 응답을 확인했다.

실제 질의 임베딩 → PostgreSQL 코사인 검색의 첫 결과:

| 검증 질문 | 첫 검색 결과 |
| --- | --- |
| 보증금 미반환 시 임차권등기명령 신청 | 주택임대차보호법 제3조의3 |
| 중개사 손해배상 책임과 보증보험 | 공인중개사법 제30조 |
| 주택 임대차 계약갱신요구권 | 주택임대차보호법 제6조의3 |

이 3개 질문은 검색 연결 점검이며 전체 검색 품질 평가가 아니다. 결과는 `vector_search_verification.json`에 보존했다.

`backend.tools.embed_property_laws`는 수집 명령과 별도로 실행한다. 적용할 manifest를 명시한다. `DATABASE_URL`은 적재할 PostgreSQL, `OLLAMA_HOST`는 설치된 모델을 제공하는 Ollama 서버를 가리켜야 한다.

```bash
./venv-wsl/bin/python -m alembic upgrade head
./venv-wsl/bin/python -m backend.tools.embed_property_laws --manifest data/law_corpus/manifest_<수집시각>.json
```

- 모델: 서버에 설치된 `qwen3-embedding:4b`, 실측 2,560차원. 기본 챗봇의 `mxbai-embed-large` 설정과 별도로 사용한다.
- 분할: 조문별 본문을 최대 1,000자로 나누며, 본문·부칙·별표 텍스트를 구분한다. `truncate=false`로 조용한 절단을 막는다. 편장절 제목만인 항목과 미래 시행 조문은 제외한다. 별표 PDF·HWP 파일 자체는 임베딩하지 않는다.
- `law_corpus_documents`: 법령·버전·모델 digest·원문 해시·시행일·수집 시각·준비 상태.
- `law_corpus_chunks`: 본문·조문 및 분할 번호·출처 URL·종류·`vector(2560)` 임베딩.
- 재실행: 저장된 청크는 다시 임베딩하지 않고 중단된 배치부터 이어간다. 법령 전체가 준비된 후 해당 모델의 이전 버전을 비활성화한다.
- 검색: 같은 모델 digest의 질의 벡터와 pgvector 코사인 거리를 계산한다. 정확 검색이며 ANN 인덱스는 만들지 않았다.
- 검증: 부분 실패 시 비활성 유지·재개·중복 방지·차원 오류를 포함해 백엔드 855개 테스트와 프론트엔드 타입 검사·린트·빌드 통과.

`embedding_report.json`에 법령별 청크 건수와 모델 digest가 기록된다. 검색 함수 `search()`는 질의에만 검색 지시문을 붙이는 [Qwen 공식 사용법](https://huggingface.co/Qwen/Qwen3-Embedding-4B)을 따른다.

## 챗봇 연결 (2026-09-11)

`backend/services/law_retrieval.py` → `chat_service.answer_question()`으로 공식 법령 검색과 생성 경로를 연결했다. 우측 컨시어지의 `tax_legal` 도구도 같은 서비스를 호출하며, 수치 검증된 답변을 다시 생성하지 않고 전달한다.

- 활성·완료 문서와 같은 모델 digest로 검색하고 미래 시행 조문·부칙·별표는 기본 답변 검색에서 제외한다. 과거 부칙의 적용례·경과조치를 현행 본문처럼 답하는 것을 피하기 위한 범위 제한이다.
- 코사인 거리 0.4 이하 후보에서 최대 4개 조문을 선택하고 분할된 같은 조문을 합친다. 합계 12,000자 한도를 넘는 조문은 잘라서 전달하지 않고 제외한다. 임계값과 긴 조문 처리는 추가 검색 품질 평가 대상이다.
- 답변 생성 컨텍스트와 화면에 법령명·조문·시행일·수집일을 제공하고 화면에서 국가법령정보센터 원문을 열 수 있다. 표시된 출처는 검색 근거 목록이며 문장별 인용 정확도 검증과 구분한다.
- 적재된 공식 문서가 없을 때만 기존 요약 코퍼스를 사용한다. 공식 검색 장애·검색 결과 없음은 요약 지식으로 조용히 대체하지 않는다. 계산 결과도 없으면 근거 부족 안내를 반환한다.
- 채팅 화면은 `POST /chat/jobs`, 컨시어지는 `POST /concierge/jobs`로 접수한 뒤 해당 경로의 `/{job_id}`를 조회한다. Redis 작업은 로그인 사용자의 소유권을 검사하며 화면 대기는 최대 4분이다. 이전 동기 API도 호환용으로 유지한다.
- 대화용 Ollama 호출만 추론을 끄고 출력 길이를 제한한다. AVM 모델 호출 설정은 바꾸지 않았다.

검증: 백엔드 860개 테스트·오프라인 고정 입력 평가 33개·프론트엔드 타입 검사·린트·빌드 통과. Docker API·프론트엔드 재빌드 후 실제 임차권등기명령 질문을 두 화면에서 실행해 답변과 원문 링크를 확인했다. 법률·세금 화면은 접수 0.064초 / 전체 24.805초, 컨시어지는 접수 0.027초 / 전체 6.095초였다. 각각 1회 측정이며 성능 보장이나 법률 답변 정확도 평가가 아니다.

재현 스크립트는 `scripts/verify_law_chat_browser.cjs`이며 실제 모델과 DB를 사용하고 임시 계정을 정리한다. 로컬 증거는 `evaluation-results/law-chat-live.json`, `law-chat.png`, `law-widget.png`에 있다. 법령 자동 갱신, 부칙·별표 기반 판단, 세법 원문 확장, 문장별 인용 검증은 후속 개선 대상이다.
