02 / FEATURES IN ACTION 실제 사용 화면

다음 기능의 판단 재료가 됩니다.

실제 실행 완료 · 제품 화면 캡처
  1. 01
    시세추정 → 후보 분석 기록

    래미안퍼스티지 84.9㎡를 입력해 시세추정을 실행하고, 분석 결과가 후보에 저장된 것을 확인합니다.

  2. 02
    자금 계산 → 후보 비교

    별도 6억원 후보에서 필요 현금·월 상환액을 계산합니다. 취득비용 960만원의 부족을 확인합니다.

  3. 03
    조건 변경 → 다음 행동

    재계산으로 자금 경고를 해소한 뒤에도 희망가가 바뀌면 다시 확인할 행동을 안내합니다.

05 / VALIDATION METHOD & NEXT STEPS 검증 방식 · 개선 계획

기대 결과와 실제 동작을 대조하고,
검증 범위를 단계적으로 넓힙니다.

DONE 어떤 방식으로 검증했나

01 · API와 저장 결과 대조회귀 테스트 806개 통과

격리된 PostgreSQL·Redis에서 API를 호출한 뒤 저장값을 재조회했습니다. 소유권 격리, 실패 시 롤백, 계산 결과와 후보 저장값의 일치를 검사했습니다.

02 · 고정 입력과 정답 비교고정·가상 평가 33개 통과

의사결정 9개 시나리오·21개 상태를 고정 시각으로 재생해 예상 경고와 비교했습니다. 계산기 16개는 수기·회귀 기대값과, AVM 1개는 가상 홀드아웃으로 평가했습니다.

03 · 검색 근거의 적중 확인시드 검색 7개 사례

질문별 정답 문서 제목을 지정하고 검색 상위 4개와 대조했습니다. Recall@4 1.00·MRR@4 0.786이며, 실제 답변의 인용 적합성 통과율은 아직 미확정입니다.

04 · 실제 브라우저에서 재현AVM·자금 연결 확인

실제 엔진으로 입력 → 계산 → 후보 저장 → 새로고침을 확인했습니다. 자금 보완 후 경고 해소와 희망가 변경 후 재검토 안내도 검사했습니다.

NEXT 앞으로 무엇을 개선하나

01 · 독립적인 정답셋 확보

계산 결과를 공신력 있는 자료·외부 계산 결과와 대조하고 기준일을 기록합니다. AVM은 지역·기간·매칭 수준별 실거래를 분리해 전체 파이프라인의 오차와 미추정률을 평가합니다.

02 · 실제 검색·대화 품질 평가

운영 코퍼스와 실제 모델로 다중 턴 대화를 반복 실행합니다. 문장별 근거 적합성·계산 설명·질문 보완을 사람 평가와 함께 확인하고, 지연·실패·폴백 비율도 측정합니다.

03 · 거래 전체 흐름 검증

권리 PDF 업로드 → 위험 확인 → 후보 비교·선택 → 실행 계획까지 브라우저 검증을 확장합니다. 후보 변경·분석 만료·실패 복구 상황에서도 정보가 올바르게 이어지는지 확인합니다.

04 · 변경 전후 품질 추적

기존 자동 고정 평가에 브라우저·실제 모델 평가를 별도 단계로 추가합니다. 데이터·프롬프트·모델 버전별 결과를 비교하고 품질 저하를 감지할 기준을 정합니다.

현재 확인한 것은 구현 동작과 제한된 평가셋의 일치입니다. 실거래 AVM 정확도·대화 전체 품질·매수 성과를 보장하는 수치가 아닙니다.
