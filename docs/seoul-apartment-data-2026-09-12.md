# 서울 아파트 매매 데이터 추가 결과

2026-09-12 실행 서비스 DB에 적재했다. 가상 매물 CSV와 법령 벡터 데이터는 변경하지 않았다.

| 항목 | 결과 |
|---|---|
| 지역 마스터 | 행정안전부 공식 API에서 서울 법정동 493개 레코드 조회·업서트 |
| 대상 지역 | 서울 25개 자치구 |
| 거래 원천 | 국토교통부 RTMSDataSvcAptTrade |
| 거래 기간 | 2025년 10월~2026년 9월 |
| 지역·월 수집 상태 | 300개 완료: 신규 수집 288개, 기존 완료 유지 12개, 실패 0개 |
| 저장 거래 | 2,187건 → 67,752건 (65,565건 증가) |
| 해제 거래 | 2,118건 — 원천 기록 보존 |
| 지역 탐색 집계 | 해제 제외 65,634건, 25개 구 표시 |

종로구·중구의 2026년 9월은 API 조회 성공 후 0건으로 저장되었다. 수집 실패나 누락과 구분해야 한다. 당월은 진행 중이며 미신고 거래가 이후 추가될 수 있으므로 이 건수를 확정 거래 총량으로 설명하지 않는다.

지역 마스터는 서울 응답만 업서트했으며 다른 지역을 비활성화하지 않았다. 기존 `ingest_transactions._ingest_one`과 `transaction_store`를 재사용했다. 아파트 원천만 선택하고 동시 요청은 2개로 제한했다. API 실패 시 빈 데이터로 교체하지 않는 기존 동작을 유지했으며, 실행 종료 후 `ingest_log` 완료 상태와 실제 행 수를 대조했다.

## 화면 검증

실제 Chrome에서 `/explore`에 접속해 25개 구의 지역 집계 표시를 확인했다. 마포구는 2,077건·186개 집계 단지, 송파구는 4,322건·251개 집계 단지를 반환하고 각각 상위 10개 후보가 화면에 표시되는 것을 확인했다. 단지 집계의 sample_count는 지역 집계의 해제 제외 건수와 같은 지표가 아니다.

첫 단지 조회에서 프론트 프록시의 ECONNRESET/500이 한 번 발생했다. 재실행에서는 마포구·송파구 모두 200 응답과 후보 표시를 확인했다. 연결 오류 원인은 확정하지 않았으며 신규 지역의 초기 조회 안정성은 별도 점검이 필요하다.

실행 자료는 로컬 `evaluation-results/ingest_seoul_apartments.py`, `probe_seoul_explore.cjs`, `seoul-explore.json`, `seoul-explore.png`에 있다. 화면 검증용 임시 계정은 삭제했다.

## 아직 포함하지 않은 범위

- 서울 외 지역, 아파트 외 유형, 전세·월세 거래 추가 수집
- 현재 판매 중인 매물·실호가 데이터 확보
- 정기 배치 예약과 과거 월의 정정·해제 재수집 자동화
- 25개 구 전체에 대한 AVM 정확도 평가

이번 작업은 데이터 범위 확장이며 위 항목까지 완료했다는 의미는 아니다.
